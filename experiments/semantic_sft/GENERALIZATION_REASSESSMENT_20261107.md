# V13之后的泛化与评测漏洞复核

结论不是“同一套原方案从通过变为失败”：旧闭环、Dev75、新12条验收分别是不同任务/输入/评分。
V13第六轮在原Dev仍为51/75，而冻结后构造的验收题为6/12，未优于V10。
新题未用于梯度训练，但作者已看过Dev错误，所以这只能叫前瞻性人工验收小集，
不能声称官方Unseen、盲测或统计上已证明泛化。小样本也不能证明模型整体无效。

## 已核验的问题

1. **训练充分性与泛化被混说。** 原V10 Train整条180/295；延长训练后第六轮277/295，
   同时Dev37→51。小集12/12及保存重载一致说明训练链路具备拟合能力，
   不支持“权重根本没生效”。轮数和LR衰减时长一起变了，不能把收益只归因于轮数。
2. **样本量掩盖语义覆盖。** 295条只有70个组、710步，FOLLOW115步，
   TURN_LEFT16、TURN_RIGHT17；共享前提只有6条。模板替换不是独立语义证据。
3. **反复围绕同一Dev改法，选模偏向风险累积。** 分组无交叉不等于从未利用Dev做研究。
   已曝光验收不得变成新的调参循环；只保留其锁定结果，不直接改写这些句子加入训练。
4. **评分单项分母有陷阱。** 原condition_exact按同一位置比值；动作已错或schema非法时，
   无法把这个数单独解释成条件理解能力。保留历史主分，新增互斥失败阶段及动作对齐后
   的条件缺失/多填/范围错误，而不是放宽评分。
5. **纯语法不等于语义，换协议不等于受控能力探针。** schema对照没有提高整条分；
   临时换成只列动作/条件的提示导致能力下降，不能据此宣称拆分式架构本身无效。
6. **数据审查不只检查字面引用。** EXP_V2_conditional_resume_04_02先让骑行者通过，
   后面变成确认行人通过，可能是模板拼接导致指代跳变，也可能本来指不同参与者。
   仅列为人工复核候选，未自动改原句、标签或审批，不能直接算“已发现错标签”。

## 实际新增的诊断，不改变旧成绩

generalization_audit.py重新用原scorer校验每条原始输出，拒绝分数漂移。
V13第六轮Dev75：51正确，2动作错误，1结构错误，4原文/契约错误，
17槽位或全局标记错误（互斥分层，按最早失败环节归类）。
72条动作对齐且schema合法，条件步骤差异为漏填7、多填5；这些是步骤数，
不能和75条整句分数直接混用。

## 新探索路线与边界

先仅在原Train295里按family和group构造四个内部组留出方案：
221/74、218/77、208/87、238/57（fit/development）；不迁移原Dev/Test，
不按模型结果选分组。每组留出只出现一次，保留原发布、原标签及审核哈希。
已有V10/V13见过全部295条，不能用它们在这些内部留出组上宣称泛化；
真正运行各折必须从原始基座独立训练，且不能把这四折当新Final Test。
目前只生成计划，未开始四折训练。

探索顺序：

1. 人工核对已标出的上下文跳变，若要修改，单独版本化并重新审核；不动已曝光验收。
2. 在内部组留出上先复现固定的十轮原损失基线，检查是否跨模板稳定，
   报告各折和最差折，不只报最高分。开发阶段不回看12条验收选方案。
3. 若条件归属仍弱，优先研究**训练过的**条件存在/原文跨度/步骤绑定监督，
   而不是继续盲目增加标量loss权重或直接提示模型换输出格式。
   新中间表示必须版本化并经过兼容与数据核验，不暗改现有完整JSON任务。
4. 如果跨组都失败，再独立测试LoRA覆盖范围等容量假设。现只适配6层global-attention的q/v，
   可列为待测因素，不能无对照认定它是根因或直接换7B。
5. 方法锁定后，后续正式判断需另一份来源独立、预先冻结且未参与研究的评测；
   本次已看过的验收分保留，不反复重试来签正式Gate。
