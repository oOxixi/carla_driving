# 2026-10-09 材料整理补丁

这是可审阅的代码、说明和本轮真实 CPU 离线输出补丁，用于覆盖到已有完整材料目录。它不包含完整数据、模型权重、240 个场景副本或完整交付包，也不会生成 ZIP。`payload/` 保持原材料目录的相对路径结构，安装后脚本才能按原包布局找到模型、数据、冻结资料及源码。

## 安装到已有完整材料目录

使用 Python 3.10 或以上版本，先查看逐文件操作：

```powershell
python install_overlay.py --package-root "D:\实际位置\挑战赛道_补齐整理包_20261008" --dry-run
```

确认输出所示的覆盖文件后执行：

```powershell
python install_overlay.py --package-root "D:\实际位置\挑战赛道_补齐整理包_20261008"
```

安装器只使用 Python 标准库。`--package-root` 必须已存在，并包含原完整材料的 `01_技术报告`、`02_源码与部署/source`、`03_训练与模型`、`06_评测说明与冻结方案`。它不会创建空的完整材料包，仅允许 payload 根目录的必要工程文件 `.dockerignore`；其余隐藏文件、隐藏目录、缓存和 Python 字节码均不复制，不删除原文件，除刷新三个目录清单文件外，不修改 payload 未提供的文件。Linux 安装时会为 `.sh` 添加用户可执行权限。

安装前会检查所有目标路径均在指定根目录内，并完整打印 `ADD`（新增）、`OVERWRITE`（覆盖现有代补文件）及 `UNCHANGED`（内容相同）清单。已存在的同路径代补说明或脚本将被 payload 版本覆盖，其他原件不受影响。安装器不提供历史备份；如需保留旧版代补文件，先复制 `--dry-run` 列出的 `OVERWRITE` 文件。输出清单就是当前 payload 的精确覆盖范围，后续新增补丁文件也按相同规则处理。

## 可选 new240 的前置资料

new240 不是官方硬性要求，不阻塞已有材料整理。该补丁只提供 README 和执行脚本，不复制冻结案例，不提供已采标签或评测结果。运行前须已有冻结／cases 资料：本脚本采用原材料中的 `06_评测说明与冻结方案/new240/freeze/` 布局，包括 `FREEZE_LOCK.json`、`acquisition_slots.jsonl`、`policy_manifest.json` 及 `scenarios/` 下的 240 个场景。其他名为 `frozen/cases` 的目录不能直接代替这些合同文件。

若原包尚无上述目录，可从已有原件 `06_评测说明与冻结方案/既有冻结与诊断原件/B2_PROSPECTIVE_BENCHMARK_FREEZE_V1_20261008.zip` 取出其中的 `freeze/` 原样放入 new240，保留所有路径及哈希；不要改 policy、seed 或场景。冻结文件缺失时执行脚本会报错，不会虚构输入。

安装后 `--list-only` 只检查并列出任务，不采集数据。实际采集需要 CARLA、支持 ModelRequest → ManeuverPlan `/infer` 的真实固定 Teacher v4 服务及身份材料，不能使用裸 vLLM `/v1` 替代。采集日志与 collector 原始接受记录不自动构成正式 case set，仍须按既有冻结 policy 检查质量、槽位、身份及泄漏。

## 安装后的文件清单

安装器支持原包 `PACKAGE_MANIFEST.json` 的 `files`（`path`、`bytes`、`sha256`）及三个清单自排除结构。安装前检查结构，安装后仅计算 payload 目标文件的体积及 SHA256，增改对应记录，并重写 `99_交付清单/PACKAGE_MANIFEST.json`、`FILE_INDEX.csv`、`SHA256SUMS.txt`。三个清单本身仍按原规则排除；不遍历或重新计算其余约 16,000 个文件的哈希。`--dry-run` 同时列出清单刷新计划。

这次刷新仅保证补丁文件记录同步，其余记录沿用原包，不能证明其余文件没有被另行修改。清单中将注明该范围，也不把材料状态改成最终交付完成。原包清单不存在或结构不同则安装前退出；应先使用原完整材料目录，或由维护者适配其清单结构。安装中若磁盘或权限错误导致中断，修复后重新运行安装器以同步清单。
