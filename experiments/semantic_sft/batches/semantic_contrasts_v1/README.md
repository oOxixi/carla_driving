这批补充是看到首轮内部Test结果之后的开发材料，不是新的独立Test，也不是Teacher采集或模型输出。
复用现有任务契约和审批流程，不修改生产模型、原驾驶代码、训练器或原冻结数据。
生成器只创建DRAFT、label=null、reviews=[]、split=UNASSIGNED，不批准、不分配集合、不训练。

本次72条已获负责人明确确认，实际批准另存`semantic_contrasts_v1_approved_20261101/`。
原待审队列不覆盖；新v2冻结Train254/Dev75，见[发布说明](../../DATASET_RELEASE_V2.md)。
下文待审说明适用于原草稿或未来重新生成的材料，不自动继承本次审批。

## 为什么补这批

首轮Train206中，TURN_LEFT、TURN_RIGHT各5次且各只有1种evidence措辞；
CHANGE_LANE_RIGHT有20次但也只有1种措辞；FOLLOW有101次。总数量达标没有带来足够词面和组合覆盖。
内部对比中，LoRA改善了schema遵循，但动作原始序列为6/12，原基座为8/12；不能因Val loss低就晋升。
后一个数字来自事后读取raw JSON的诊断，不是预注册主评分；不是原线上few-shot/语法约束整套方案的对比。

## 补什么，不补什么

| 对照方向 | 重点 |
| --- | --- |
| 并线 / 转弯 / 跟随 / 保持 | 词面改写、相同背景不同请求，禁止把他人方向复制成本车方向 |
| 条件范围 | 同一个条件绑定并列任务；独立条件分开绑定；不补默认条件 |
| 超越 / 绕障 / 普通变道 | 同一慢车背景下，仅按明确请求拆任务，返回和调速不丢失 |
| 禁止事项 | 禁止转弯不扩大为禁止变道；禁止靠边停车不扩大为禁止普通停车 |
| 多目标与步骤 | 顺序变化、任务删除、背景变化必须导致相应标签变化，目标不串绑 |
| 矛盾 / 非矛盾 | 同时互斥与先后执行区分；目标未选定与唯一目标区分，不能一律HOLD |

六类各12条，共18个四句对照组。新增草稿覆盖14种动作，包括左转11次/8种措辞、
右转13次/9种措辞、右变道7次/5种措辞。措辞是evidence字面计数（含顺序词等边界差别），不是独立语义模板数量。
数字是**待审提案**统计，不是已批准训练覆盖或效果提升证据。
不是18个已证实独立的新模板：16个拟定新组，2个沿用旧Train组：
`expansion_v2_yield_follow_03`、`expansion_v2_ambiguity_04`。
对照组是防泄漏的保守聚类，不代表每句都只改了一个词，或不同组已证明语义独立。

不复制旧12条Test，不把它们换数字/目标后作为新增语料；旧Test仍作为保护集合排除。
本批没有新Final Test，旧Test已披露且已用于指导开发方向，后续不再称其为调参后的独立成绩。
原3条“禁止超车/不增加车速”等契约缺口继续隔离，不通过新批绕过或扩大禁止语义。

## 负责人审核入口

本机和服务器独立工作区相同相对路径：

`artifacts/semantic_sft/semantic_contrasts_v1_20261101/`

- `review_index.md`：18组原句和动作链概览。
- `draft_review_sheet.md`：72条完整目标、条件、方向、数值、证据和禁止事项。
- `draft_review_queue.jsonl`：待审提案，不含任何批准标签。
- `group_review.json`：旧组关联及结构相似的旧Train/Val组，供跨批分组复核。
- `report.json`：原Train覆盖、提案覆盖、生成器和交付文件哈希及明确未训练声明。

特别复核：

1. 仅有状态条件“某人通过后”与明确“先让某人通过”的任务拆解差异。
2. 同一个条件的并列动作覆盖范围，以及“然后/再”的顺序是否被误写成条件。
3. “不要求超越”是没有该肯定任务，不自动升级为全局禁止超车。
4. 矛盾样本HOLD及requires_confirmation，与未矛盾的对照是否区分准确。
5. 新旧近义组是否应并组；同组不能跨Train/Val。结构签名相同只是排查提示，
   并不表示所有HOLD、所有相同动作链都必须合成一组，也不表示无相同签名就独立。

审核之后才能登记真实批准、决定整组集合并另立数据版本。原206/51不覆盖，不能只用新72条替代原训练材料。
下一轮需保留旧能力回归，并在开发验证集上用真实生成的动作/条件/目标指标选择候选，不能只依赖Val loss。
不可根据已曝光12题在原epoch1/2/3中反复挑选最好，再把同一Test包装为独立提升；最终需新独立测试。
