# 统一多模态目标跟踪：C1 动态实验

## 结论

C1 当前未达到可以继续 C2 的条件：前车的有效轨迹出现 3 次 ID 变化和 6 次中断后恢复；相邻车虽有持续视觉轨迹，但 60 帧仅 3 帧有三维点簇，没有达到三维确认。7 次自然的检测通道切换中，2 次能核验同 ID，5 次因至少一侧身份处于歧义或未关联而无法判断。不得把“无法判断”算作失败或成功。

**目前仍是实验原型，没有驾驶权限。** 已停止 C2 减速加速和 C3 遮挡切入，等待 C1 问题解决并在新数据中验证。本次只有一个重建的场景，参数及实现未经独立场景验证。

## 场景与真实边界

- CARLA 0.9.16、Town05_Opt，直线路段，一辆自车和两个目标。自车 7 m/s、前车 5 m/s、邻车 6 m/s，60 帧、20 Hz，首尾跨度约 2.95 秒。车辆是通过每帧脚本设置位姿的运动学运动，不是完整的车辆动力学、跟驰控制或自然交通，不能用来证明雷达多普勒或真实驾驶表现。
- 实际普通 LiDAR 为 32 线、224000 点/秒、20 Hz、上下视场 +10/-30 度，丢点 0.45/0.4/0.8；相机 800×450，YOLO 640×640，置信度 0.35 正式、0.20–0.35 辅助，NMS IoU 0.45。同步相机、LiDAR、语义 LiDAR、Radar 帧号相同，时间戳误差不超过 1 ms。
- 不提供人工检测框；检测、方案 C 和统一跟踪按传感器观测执行。只使用原方案 C 自适应聚类半径，上一任务单个样本的 0.52 m 没有推广到 C1。正式链路仍按既有方案使用同步 Radar；实验性统一身份关联没有使用 Radar，因为本次运动学回放无法验证雷达速度证据。
- 首次采集由于在出生后第一次世界 tick 前读取车辆位置，错误地将车辆移动到地图原点。该数据已标记 INVALID，未纳入结果。修复后按相同场景参数重采。
- 重采后的第一版回放发现用“框中心靠近”处理冲突会误伤相邻、不相交车辆，修正为框相交并靠近后进行竞争处理，加入回归测试。随后补充速度证据不足保护：至少两次三维测量才输出速度。原始、修正前速度保护、最终回放均单独保留；因此本次结果是开发回放而非独立验证集表现。

## 如何读取指标

在传感器决策全部冻结后，才利用 Actor 包围盒投影与检测框的 IoU ≥ 0.30 做逐帧一对一匹配，再用语义 LiDAR 在 8 cm 内最近邻近似核验选中的点。框匹配和语义近邻均可能出错，不能当作人工逐帧复核。AMBIGUOUS 不算有效身份匹配；VISUAL_ONLY 可以计入视觉轨迹连续性，不能计入三维确认。

ID Switch 是同一真实车辆两次有效匹配到不同 ID 的次数，允许中间存在未匹配帧；Fragmentation 是有效匹配中间至少有一帧无有效轨迹后重新匹配的次数。该定义下两项可能同时记录同一段中断。连续性是可见帧中存在有效身份关联的比例，不代表每帧都有三维位置。

| 指标 | 前车 | 相邻车 |
|---|---:|---:|
| 可见帧 | 60 | 60 |
| 检测框匹配 | 52/60 | 60/60 |
| 轨迹匹配，包括 VISUAL_ONLY | 46/60，76.7% | 60/60，100% |
| ID Switch | 3 | 0 |
| Fragmentation | 6 | 0 |
| 首次实验三维确认 | 从首次匹配算第 5 帧 | 未确认 |
| 实验确认帧数 | 31 | 0 |
| 检测框匹配但无选中三维簇 | 13 帧 | 57 帧 |
| 选中点语义近似属于该车 | 225/225 | 9/9 |
| 点级条件 Precision | 100% | 100%，仅 9 点 |
| 速度矢量误差 P50/P95/最大值 | 0.323 / 2.827 / 5.176 m/s，34 个样本 | 2.031 / 3.370 / 3.519 m/s，仅 2 个样本 |
| 表面位置代理到车辆中心的距离 P95/最大值 | 1.882 / 1.974 m，37 个样本 | 2.463 / 2.464 m，仅 3 个样本 |

速度真值来自相邻仿真帧车辆包围盒中心的位移除以时间。滤波的是可见表面点簇中位数，因此其速度可能受到被看到的表面变化影响，不能等同于可靠的车辆中心速度。表格中的“表面代理到中心距离”包含车辆本身的表面到中心偏移，**不是车辆中心定位误差**；本实验没有足够证据恢复完整车辆中心或尺寸。

跨通道自然切换共 7 次：2 次可核验 ID 保持、5 次无法评价、0 次在可评价的两端看到 ID 更换；ID Switch 总数中仍有 3 次发生在其他时间。逐帧轨迹 10456–10458 中前车从正式→辅助→正式，均为 T-0007。另有时段检测类别在 car/truck 之间变化，同时候选框可能重叠或三维点不足；当前严格类别和跨通道三维证据门限会拒绝匹配，且连续三帧未匹配即 LOST，可造成断轨。不能仅凭此实验断言这就是所有断轨的唯一原因。

本样本按上述真值匹配与语义点核验，没有观察到两个实验车辆的所选点混合或已确认轨迹转到另一实验车辆；未匹配的背景检测没有完整人工标注，不能把这视为全场景零误确认。所有 60 帧正式点云处理重算一致；正式及辅助所选点均未重复分配；所有 FOLLOW 权限始终为 false。

## 实现与文件

实验分支 `experiment/3d-target-disambiguator-20261117`，工作树 `/home/tiaozhansai/carla-disambiguator-experiment-20261117`，生产工作树未修改。

- `tracker.py`：统一 `T-` ID、跨通道的一对一传感器门控、卡尔曼预测和五状态管理。跨通道续接须有双方三维信息；多目标竞争、点重用和不确定空间关系拒绝强行绑定。速度不足两次三维观测不输出。确认不授予 FOLLOW。
- `collect_c1.py`：隔离 CARLA 实例上的 60 帧场景采集，观测和真值分别保存。
- `run_c1.py`：正式检测先执行原方案 C，保护正式框及点，再独立处理辅助点；保留 Target3DDisambiguator 空间证据，冻结观测及轨迹。不会读取 oracle 目录。
- `audit_c1.py`：冻结后匹配 Actor 真值及近似语义点，产出逐帧和指标。
- `test_unified.py`：覆盖双向通道迁移、无三维证据不迁移、竞争、重复点、丢失、时间顺序、相邻检测框和速度初始化。与上一阶段测试合计 28 项通过。

有效数据目录 `artifacts/runtime/unified_tracking_c1_retry_20261117/`：`predeclared_plan.json`、`capture_manifest.json`、`frozen_sensor_decisions.json`、`offline_audit.json`、`summary.json`；`frozen_sensor_decisions_initial.json` 保存修正关联前的结果。首次错误采集位于 `artifacts/runtime/unified_tracking_c1_20261117/INVALID_CAPTURE.txt`。

## 下一步待验收方向

先分析并改善间歇三维点簇、类别抖动、短暂失检和门控冲突造成的断轨；保留歧义机制，不能通过强制合并或使用 Actor 真值提高表面连续率。应先在开发数据中明确方法，再用独立采集的动态路段验证 ID、碎片化、通道切换、确认误报、速度和位置；通过后再进入 C2。
