# 多档位补样与速度Head续训

结论：完成补样、1600步专项训练和选模后复核。**40个检查点均未通过完整选模条件，保留原robust-v3。** 第760步只作为探索结果存档，不能部署或标为正式Gate。

## 数据

原CARLA端口2100下线。临时实例2120/2124均在有界等待内未能通过地图RPC，均已停止；启动日志保留，没有替换生产服务。没有声称采得新路况。

替代方案：从原内容绑定的Train/Val分别抽取低风险Town03系列的真实RGB和请求上下文，每类选6/2个原组。保留原RGB、候选目标与场景条件，只构造多档位指令和速度监督。新增 **336 Train（24原组）/80选模Val（8原组）**，每档两种说法；Train档位10/14/17/20/23/26/29，Val档位11/16/21/25/28 km/h。

- 明确设速/减速：只监督第一步速度；减速中的初始30 km/h是受控任务条件，不是该RGB中的实车测量。
- 左换道后设速：只新增第二步数值监督，不把后续速度写进首步。
- 跟车：保留原先绑定的前车，只对超过口述上限的值加损失，不把上限当巡航速度。
- 新标签来自指令合同，不是新采集的Teacher闭环标签。所有RGB按原清单SHA核验，原组只在自己原有split使用。新增Train、选模Val、旧128探针的样本/请求/组键/RGB SHA/语义请求指纹交集均为0。替代方案没有道路ID分离证据；这些不是新地图、独立道路或真实闭环成绩。

## 训练及选模

从原robust-v3固定SHA起训，不从已退化的V1速度候选继续。复用先前原5856/1108的冻结特征缓存，核验缓存哈希、原数据预检和原Head可复现输出。只更新 `target_speed_head.weight`、`target_speed_head.bias`（4100参数），不改结构。原Train的masked Huber与新样本精确速度、跟车单侧上限、216组相邻档位的成对响应损失共同训练。

GPU 2，AdamW `1e-4`，1600步，每40步检查。预定门槛：新Val各类原始Head及Adapter命中不退化，精确速度误差和跟车超限误差不退化，精确任务总命中增加；原Val各切片MAE最多+0.01 m/s，安全关键不得退化。只在权重冻结后复核旧128条，不以其结果选步或再次调参。9个其他Head在新Val与旧探针上的输出逐字节一致。

## 结果

| 任务 | 新选模Val：原版→第760步（每类20） | 旧128开发探针：原版→第760步（每类32） |
| --- | ---: | ---: |
| 单独设速 | 6→5 | 8→6 |
| 减速至指定值 | 0→6 | 8→8 |
| 换道后设速 | 4→4 | 8→5 |
| 跟车目标及速度上限（原始Head） | 10→14 | 16→24 |

设速/减速/组合三类按完整动作序列和±2 km/h判定，原始与Adapter命中相同。跟车仅核对目标与上限；Adapter后的上限/目标命中分别维持20/20和32/32，不代表动态跟车通过。

- 新Val组合速度MAE 9.84→4.71 km/h，但命中没有增加；旧探针组合MAE反而5.18→6.33 km/h。
- 旧探针组合请求跨12→27 km/h时，预测平均跨度0.67→1.93 km/h，响应改善但远小于实际请求的15 km/h差值。
- 原Val总体MAE 0.3782→0.3894 m/s，设速0.5029→0.5699，减速1.0976→1.3031；安全关键0.5315→0.1904，后续步骤1.0826→0.1494。不能以部分切片进步掩盖退化。

当前补样方案与冻结融合特征上的线性Head不足以稳定保持数值精度。下一步优先做**显式数值条件化的可学习速度Head**对照：为明确的速度目标提供带掩码的m/s输入，区分精确目标与上限，只更新速度分支，保留旧128作为开发回归、再用独立新组验证。不要直接覆盖模型速度后将结果计为Student准确率，也不建议只增加当前训练轮数。
