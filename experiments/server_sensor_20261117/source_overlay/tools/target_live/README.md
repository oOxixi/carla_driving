# 真实 CARLA + Qwen 目标绑定展示

页面读取服务器运行日志、CARLA 追车摄像头和提交给 Qwen 的真实前视画面，不通过手动点击模拟模型答案。`record_stream.py` 将摄像头 JPEG 帧保存在服务器，用于运行结束后的回放。页面可切换历次运行；事后将检测轨迹与 CARLA 场景角色关联，仅用于评估，不作为模型输入或传感器证据。

运行链路：RGB/LiDAR/Radar → 检测器和传感器追踪 → 语言目标与候选筛选 → 标记单视角候选框并送入 Qwen → 模型一次输出动作与目标组合或“不确定” → 最新帧证据验证 → 规划编译及原有车辆安全链。模型输出的字母和目标身份在 `model_grounding` 留存；动作展开和约束仍由程序完成。接口新增可选 `target_grounding` 和 `model_grounding` 字段，使用这一能力时客户端和 Qwen 服务必须运行本分支的相同协议版本。

实际运行使用服务器上现有 Qwen/Qwen3.5-2B vLLM、真实 CARLA Town03_Opt、RGB/LiDAR/Radar 和既有 ONNX 检测器。模型画面为 224×224，彩色空心细框和标签来自检测器而非 CARLA 对象真值；新布局把彩色编号置于画面顶部的独立黑条，不覆盖目标，框色是标注而非车辆颜色。图像框映射已按缩放加黑边转换；四视角拼图暂不画框，不假装支持多视角视觉目标编号。

本次三次真实运行的 JSONL、摘要、模型输入和回放都保存在 `artifacts/runtime/target_live/`。前两次多车场景中，场景事后关联把模型选中轨迹对照到相邻干扰车，目标绑定未通过；第三次单车场景关联到预设前车，但检测置信度约 76.5%，低于当前 80% 门槛，车辆保持等待。此门槛未校准，不构成准确率或安全性结论；尚未证明可靠的闭环跟车和 150 ms 端到端时延。

第四次对同一多车指令重测了顶部编号布局：模型仍选择 C-0002，事后轨迹关联为相邻干扰车；安全验证因为检测置信度不足未放行。单次测试不能证明布局对准确率有统计意义的影响。

新增真实 CARLA 同帧 RGB–LiDAR 投影关联和轨迹、车道筛选：按传感器姿态投影激光点至检测框，重叠框共享点不参与关联，点数不足则位置和距离未知；车道使用传感器位置结合地图 waypoint，跨道路编号仅在唯一前向车道连续时标为本车道。第 9 次为默认较高密度传感器对照：前车关联约 28.6 m、本车道；另一目标点云不足、距离和车道未知，故未唯一绑定，模型仍选未知目标且计划被拒绝。该关联为原型，尚未完成充足的定量标定、遮挡、背景点误匹配和多天气验证，不能当作安全认证。

注意：既有场景角色对照使用近似距离及图像位置，尚未与投影关联完成独立校准，不能当作确定真值；新投影几何在校准验证完成之前仅供筛选展示，目标相关危险动作需继续确认。
