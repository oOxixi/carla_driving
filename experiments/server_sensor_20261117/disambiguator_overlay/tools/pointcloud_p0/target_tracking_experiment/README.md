# 任务 A：extra_250_25 连续帧目标跟踪实验

## 一句话结果

在重建的静态场景中，30 帧中有 19 帧同时取得满足实验性空间分离条件的两个点簇，15 帧中两条轨迹同时达到实验用的 3/5 帧确认规则。两条轨迹分别保持同一 ID；这只是离线研究状态，不能直接用于驾驶控制。每帧两组点均未重复分配。该测试不能证明动态场景、交叉、遮挡下身份稳定。

## 实验条件和边界

- 该样本原来只有一帧。为了取得真实连续输入，在独立 CARLA 0.9.16 实例中按照原场景的地图、位置、两辆车、天气及安装参数重新采集 30 帧，间隔 0.05 秒，总跨度约 1.45 秒；目标车辆静止。帧 17386–17415 的相机、LiDAR、Radar、语义 LiDAR 帧号相同，时间误差不超过 1 ms。
- 普通 LiDAR 实际配置：32 线、224000 点/秒、20 Hz、垂直视场 +10/-30 度；General Drop-off 0.45、Zero Intensity 0.4、Intensity Limit 0.8。未关闭丢点。
- YOLO 使用现有 ONNX 模型、640 输入、NMS IoU 0.45，正式阈值 0.35，辅助候选 0.20–0.35。0.52 米仅用于该样本辅助候选，不修改生产阈值，不扫描其他半径。
- 用先前人工复核的两个检测框作为该静态重建样本的视觉初始化提示。该做法适合验证此个案，不能作为动态场景中通用的初始化方法。
- 所有正式检测先按原方案 C 分组和分配；正式检测框内点及已选点先保留，辅助候选仅使用剩余点。逐帧用原输入重算方案 C，结果与辅助处理前完全一致。原正式方案 C 仍使用本次同步 Radar；实验性的辅助跟踪没有使用 Radar。
- 决策脚本不读取 actor 真值或语义 LiDAR；传感器决策文件先保存，再用分开存放的 actor、语义点数据审计。语义点按 8 cm 最近邻对应普通 LiDAR 点，属于近似核验，不是逐点完全可靠的物理真值。

## 简单说明状态

- VISUAL_ONLY：本帧只有检测框或无法形成有效点簇，不输出旧的三维位置。
- TENTATIVE_3D：本帧有候选点簇与分离证据，但最近五帧有效证据不足三次。
- CONFIRMED_TRACK：最近五帧至少三帧存在匹配的有效三维观测，且本帧满足分离条件；这是未标定实验规则，并不赋予控制权限。
- AMBIGUOUS：本帧无法判定点簇分离、存在点重复、关联冲突或没有当前观测；不强制选择或暴露预测位置。
- LOST：连续三帧未匹配或帧间隔超过实验门限；不输出旧位置。遇到竞争关联时拒绝强行分配。

该版本只在本实验中按通道、类别、框位置及三维门限关联，并使用常速度卡尔曼滤波。辅助和正式轨迹没有实现跨置信度通道迁移、车道匹配或 Radar 验证。5 帧中 3 帧不是要求连续 3 帧；实验参数事先写入 `predeclared_plan.json`，未做独立标定。

| 辅助候选点簇 | 25/30 帧形成被选中的至少 3 点簇；其中部分帧缺少另一目标的可靠簇，因此不能确认两车独立。 |
| 辅助点级 Precision | 174/174 = 100%。计入所有被选辅助点；语义最近邻核验，未匹配点会保守计入分母。 |
| 辅助点级条件 Recall | 174/478 = 36.40%。分母为已经通过辅助框及筛选的近似目标点；不是整车全部 LiDAR 点的召回率。逐帧点数随随机丢点变化，不能拿第一帧 68.75% 代表整段。 |
| 不同车辆混合 | 所选正式点与辅助点均未发现另外一辆实验车辆的语义近似点；本场景 30 帧观察到 0 次，不能证明所有场景为 0。 |
| 表面测距绝对误差 | 在 25 个形成辅助簇的帧中 P95 约 0.595 m，最大约 0.609 m。计算为选中点最近水平距离对 actor 包围盒最近水平距离，二者不是完全相同的可见表面参考；第一帧为 +0.164 m。样本少，P95 不稳定。 |
| 位置估计及不确定性 | 输出是所选点表面中位数的卡尔曼滤波代理，不是车辆中心或占据范围。19 个有可用位置的帧，模型内部每轴标准差中位数约 0.243 m；该数依赖假设噪声，未标定，不能当作真实误差上界。 |
| 正式链路、点归属 | 30/30 帧正式结果重算一致，30/30 帧正式点与辅助候选点无重复；只覆盖此回放输入。 |
| 处理延迟 | 当前离线回放 P50 约 135 ms、P95 约 176 ms，包含 ONNX、重复计算正式链路及审计数据生成；不是可与生产 Baseline 直接比较的实时延迟。 |

状态帧数：正式轨迹临时 4、确认 15、歧义 3、仅视觉 8；辅助轨迹临时 4、确认 15、歧义 6、仅视觉 5。样本中未达到 LOST 条件。状态变化表明静态场景中单帧点簇仍会随随机采样间歇缺失，不能把每帧缺簇直接解释成车辆消失。

## 实现和复现

工作树：`/home/tiaozhansai/carla-disambiguator-experiment-20261117`，分支 `experiment/3d-target-disambiguator-20261117`。所有变动为实验目录下新增文件；原 `before-VLM-sense` 工作树未修改。

- `tracker.py`：状态管理、一对一门控、冲突拒绝、常速度卡尔曼滤波，始终禁止 FOLLOW。
- `collect_sequence.py`：在独立 CARLA 实例重建场景，采集并分开保存观测和真值。必须只对隔离端口运行；会加载 Town05_Opt。
- `run_sequence.py`：先处理正式通道、再处理辅助通道，固定本样本 0.52 m，调用已有 Target3DDisambiguator 提供几何证据，冻结逐帧结果。
- `audit_sequence.py`：只读取冻结结果后使用语义 LiDAR 和 actor 核验。
- `test_tracker.py`：覆盖 3/5 确认、丢失、仅视觉、点重用、竞争关联、时间倒退和门限冲突；本模块及原三维区分测试共 20 项通过。

数据、逐帧状态及结果位于 `artifacts/runtime/target_tracking_extra25025/`：`predeclared_plan.json` 是预先记录的实验参数；`capture_manifest.json` 是传感器配置及帧清单；`frozen_sensor_decisions.json` 是无真值的决策；`offline_audit.json` 是逐帧真值核验；`summary.json` 是统计汇总。`oracle/` 和 `frames/` 数据均保存在服务器。

重要限制：不做多帧点云拼接；只关联单帧检测与单帧簇。没有动态目标、交叉、遮挡恢复、身份切换、多个同类竞争目标或独立新场景验证；也未进行参数标定、控制集成或实时验收。不得将本次实验确认状态、0.52 m 或空间门限当作正式方案。
