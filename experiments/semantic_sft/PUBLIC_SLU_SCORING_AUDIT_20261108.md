# 公开 SLU 数据筛选审计：评分要求与真实可用性

日期：2026-11-08。范围：MAC-SLU、MIVS 公开 Train；仅语义数据审计。

结论：**不能把车舱 SLU 数据直接等同于驾驶语义监督，更不能当作比赛闭环成绩。**
本次没有启动训练、没有生成驾驶标签、没有更改当前模型/生产服务/7B方案，没有推送远端。

## 1. 评分依据与解释边界

主审计依据为用户提供的《2026年度中国青年科技创新“揭榜挂帅”擂台赛人工智能领域主擂台赛-初审评比方式及评分细则》：

- 第2-3页：基础算法50分、部署50分；自然语言意图解析单列8分。
- 第4-6页：允许在未提供官方统一基准时自建数据，必须说明来源、规模、标注和评测口径，冻结脚本并可复现。
- 第7页：与榜题方案、组委会规则冲突时，按文件声明的优先级处理；不得自行替官方解释冲突。
- 原《XH-202602比赛方案》第7-9页保留三类驾驶工况、单步/组合/应急指令及多模态场景覆盖要求。
- 不使用原方案40/60分的表格来替代用户此次指定的50/50初审审计表；这不代表确认了任何新的官方通知。

以下是训练数据的筛选/取证对照，**不是官方得分计算器，也不自行指定“整条JSON精确匹配”就是官方意图准确率定义。**

| 评分项 | 对数据/验证的实际要求 | 本次审计结论 |
| --- | --- | --- |
| 自然语言意图解析8分：基础≥95%；清晰指令100%无误判对应满分档 | 驾驶动作、顺序、对象、方向、单位/数值、条件和禁止项有明确标签；按冻结口径报告正确率 | 两库可辅助多意图/槽位训练；没有当前完整驾驶标签，不证明达标 |
| 模糊指令安全策略2分 | 歧义被正确识别；确认/减速/停车兜底实际安全生效 | 空语义不是歧义标签；需专门标注与闭环验证，不能自动填HOLD/STOP |
| ASR3分及方言/50dB噪声2分 | 音频、转录、噪声/方言口径及实际识别结果；解析时延也须实测 | 本次只审计文本标签；没有下载/验证MAC音频，不提供此项证据 |
| 四路信息融合5分 | 语音、视觉、车况、环境四类信息确实影响决策 | 没有与CARLA同源的四路数据，不支持此项成绩 |
| 语义-动作对齐5分、动作合理性5分 | 语义解析后，结合真实路况执行；动作匹配、平顺合规 | 文本槽位正确不等于车辆执行正确；需模型输出与安全覆盖分开留痕 |
| 三级闭环15分，权重30%/40%/30%并扣违规 | 三类场景的完整任务与违规记录 | 公开文本样本不能替代5/8/6km等工况验证 |
| 端到端时延2分、连续稳定性2分 | 语音输入到执行的时序证据；连续30分钟运行 | 本次未测；此前暂不考虑延迟不等于取消评分要求 |
| 部署50分 | FLOPs、异构利用、核心性能衰减及创新；同源冻结口径对比 | 数据规模/LoRA训练成功不证明压缩收益、正式Gate或部署得分 |

## 3. 筛选结果：候选不是正式Train

| 数据集 | 原Train行数 | 辅助引用候选 | 隔离/待复核 | 其中候选含≥2个标注意图 |
| --- | ---: | ---: | ---: | ---: |
| MAC-SLU | 18,000 | 6,861 | 11,139 | 1,327 |
| MIVS | 84,049 | 30,727 | 53,322 | 15,936 |
| 合计 | 102,049 | 37,588 | 64,461 | 17,263 |

“辅助引用候选”仅表示通过本轮保守机械筛选，**仍未通过辅助任务输出契约、原始分组隔离、人工标签审核及许可准入**。没有导出可直接喂给现有Trainer的SFT。

主要问题计数（同一行可命中多项，不能相加当总剔除数）：

| 问题 | MAC | MIVS |
| --- | ---: | ---: |
| 没有可用标注意图 | 5,306 | 8,000 |
| 至少一个槽值不是原文连续片段 | 5,251 | 35,494 |
| 命中受保护文本规范化精确哈希 | 52 | 1,106 |
| 包含评测整句或保守拆分片段 | 370 | 19,242 |
| 涉及安全辅助功能控制，需复核 | 48 | 3,797 |
| 出现驾驶相关词但不能自动映射动作 | 92 | 2,743 |

MAC另有5,871行的分句数量与有效标注意图数量不一致，不能默认一分句一完整动作。

驾驶相关词复核队列保留1,253行非评测命中的Train样本及原标签；`current_task_label=null`、`annotation_status=UNREVIEWED`。它不是1,253条已确认驾驶指令。

例子（全部来自Train，不取自Test）：

- “把行车闭锁设置成16千米每小时”：设置门锁触发速度，不是SET_SPEED(16)。
- “车速自动关窗切为每小时60公里”：设置自动关窗条件，不是SET_SPEED(60)。
- “窗帘左转一点”：不是车辆TURN_LEFT，而且原标注为空。
- “关闭自动紧急转向”：控制安全功能，不是要求车辆立即转向或执行避障。
- “设置ACC跟车距为4”：原语义为空；不可补造FOLLOW(gap_m=4)标签，原句也未明确米。

**直接准入当前14动作、1-8步驾驶语义契约：0条。** 这里的0表示尚未获得可直接使用的完整标签，不表示人工复核后绝无可利用样本。

## 4. 评测排除与局限

- 加载现有Frozen Test、独立Validation注册表、内置提示/Dev/Probe/冻结holdout哈希，排除当前已审核Train重复。
- 复核上次盘点中的27份评测/隔离资源，包含回归库及B1各发布Val/Reserved/Calibration/Quarantine。
- 本机22份文件与服务器记录仅CRLF/LF字节不同；工具明确记录原哈希、本地哈希和`CRLF_TO_LF_ONLY`，其他字节变更直接中止。
- 上游MAC Dev/Test仅自动提取文本排除信息；MIVS Valid/Test同样仅作文本排除，不展示/输出标签。
- 全部资源规范化精确保护哈希共23,974个；另保存保守连接词拆分后排除哈希。
- 除精确命中外，排除Train内包含长度≥8的受保护评测整句/连接词拆分片段；这是保守过滤，可能误隔离正常短语。
- **没有宣称语义近重复、改写、所有共享模板或合成原料组已完全无泄漏。** 缺少上游原始component/group provenance；辅助候选因此继续阻塞，不发布新Train/Val。
- 正则只触发复核，不是完整安全识别器；未命中也不证明样本安全或适合驾驶任务。

## 5. 缺失标签与下一步

当前仍需补足的驾驶语义监督，不可从这两库自动补造：

1. 单步/组合/应急动作与完整顺序；省略、否定及纠正指令。
2. 目标/方向和原文证据；语义目标文字与运行时Actor ID分离。
3. 速度/车距及单位；区分“车速参数”和门锁、雨刷、音量等功能触发阈值。
4. 条件归属：共享前置条件、只约束后续一步、完成后恢复、先后约束。
5. `prohibited_actions`与`requires_confirmation`；不能把未知/无标签都当安全HOLD。
6. 语义只提取驾驶员意图；实际设速和跟车冲突交由真实路况、安全分层约束，不把执行覆盖反写为原句标签。

推荐推进顺序：

- 先复核驾驶词队列，少量提取确实属于驾驶意图的原句，补齐当前格式全部标签、跨批分组后由用户确认。
- 优先补条件作用域、否定/确认、对象与数值归属，不用大量音乐/空调数据稀释当前驾驶目标。
- 若试验公开辅助训练，使用独立任务提示与原生intent/slot结构，不硬压进14动作；先做小规模受控消融，不能直接混入现有SFT。
- 从同一固定2B底座、相同受控配置比较“驾驶数据”与“驾驶+辅助数据”；仅在训练内分组验证/开发集选型。已评测holdout不再用于调参，不承诺提高正确率。
- 最终另做冻结评测、Qwen输出因果对照和CARLA执行验证；模型语义正确与SafetySupervisor最终覆盖必须分别报告。
