# 不经 Qwen 的传感器跟车探索（2026-11-12）

## 范围

用户提出跟车不交给模型，依据传感器执行。现有 C `FollowingController` 已使用前车距离、闭合速度、期望车距和 TTC；A 状态机与 D 安全仲裁保留。复制先前场景，实验副本移除“每条语音必须调用 Qwen”的项目场景策略；所有控制使用 `perception_mode=sensors` 和 `scenario_facts_mode=perception`，场景真值只用于离线评估。首次单车启动 CARLA 发生 Signal 11，0 帧，保留 `carla_first_crash.log`，重启后完成。

重要限制：场景入口 `resolve_scenario_command` 将场景 `FOLLOW` 转为 `SET_SPEED`，因此这些实验是“场景指令触发设速，C 自动用前向传感器限速”，而非已实现身份绑定、最近同车道语义的标准 FOLLOW 指令。`longitudinal_state=FOLLOWING` 只说明 C 检测到前向距离，不单独证明跟随了指定目标。正常 Qwen 语音路径与安全规则均未更改。原场景规定使用 Qwen 是本仓库场景配置，不代表已经核实官方必须这样设计。

## 实验结果

| 场景 | Qwen | YOLO | 控制帧 | 传感器距离可用 | 自车位移 | 结果 |
|---|---|---|---:|---:|---:|---|
| 单前车初始 20m | 不用 | 使用 | 300 | 116/300 | 3.37m | 指令被安全覆盖，后停车；无持续跟车，碰撞 0 |
| 同一单车场景重跑 | 不用 | 不用 | 300 | 299/300 | 58.82m | 自车末速 3.03m/s，前车目标速度 3m/s；中心距约 24.56→9.16m，碰撞 0 |
| 多车初始 40m | 不用 | 使用 | 150 | 0/150 | 0m | 安全覆盖停车，碰撞 0 |
| 多车初始 60m | 不用 | 使用 | 150 | 0/150 | 2.41m | 安全覆盖停车，碰撞 0 |

纯传感器单车组证明既有规则控制器在这一次简单、有限的仿真中能产生跟随效果，不证明完整跟车指令语义、多车正确绑定、所有条件安全或实车可用。车辆中心距不等于车辆净距。场景验收显示 SUCCEEDED 的单车组只覆盖通用规则，且直接指令反馈 SUCCEEDED 的含义是达到 SET_SPEED，不是已证明目标跟车。

## 两次单车结果为何不同

两组在运行第 42 帧（约 2.1 秒）均出现一次前向距离未知，下一帧又恢复约 26.4m：启用 YOLO 时，有视觉前车、无距离触发 `C_FRONT_CAR_VISUAL_HAZARD_WITHOUT_RANGE`，当前指令收到 `SAFETY_OVERRIDE` 并终止，车最终停车；关闭 YOLO 时缺少这项视觉告警，控制继续。两组随后轨迹分叉，因此后续 116/300 与 299/300 不可当成对相同轨迹单因素性能对比。不能为追求运动而简单去掉视觉安全告警；应设计短时不确定下的减速/停车、连续一致后经验证的恢复机制，以及超过时限的安全保持。

启用 YOLO 单车组，184 帧控制链前向距离未知，其中 79 帧旁路 `ShadowSensorFusion` 有 SAME 融合位置；事后这 79 个位置均落在唯一前车三维包围盒内。此证据仅涵盖单车，不能用于证明多车正确绑定；旁路未进入 C 或控制。
