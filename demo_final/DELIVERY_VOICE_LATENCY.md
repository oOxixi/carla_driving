## 时延长短原因分析

1. 首轮约 5s vs 后续约 0.2s：模型冷加载（936MB 权重 + CUDA/FP16 初始化），与算力无关，可启动预热消除；
2. ASR 110ms vs 250ms：主要由音频时长决定（1.2s → 110ms，3.2s → 250ms），约等于 50ms 固定开销 + 50ms/秒音频；
3. 整轮 0.6s vs 3-5s：简单指令语音直出（不调 Qwen）约 0.6-0.7s；复杂/未识别指令等待 Qwen 云端返回 2.4-5.3s；
4. Qwen 1843ms vs 4641ms：云端 API 网络与排队波动，与本地设备无关。

## 更高算力能否减少纯语音识别时间

- 结论：能，但收益有限（约 1.5-2 倍），且不是当前链路主要瓶颈。
- 原因：SenseVoiceSmall 为约 2.4 亿参数小模型，单条 batch=1 推理受启动/调度开销与内存带宽主导，而非峰值算力；4060 上已是"1 秒音频约 0.1-0.25 秒识别"。
- 估算（同模型同代码）：纯 CPU 600-1200ms；RTX 4060（当前）110-250ms；RTX 4090 约 70-130ms；A100/H100 约 60-120ms，之后趋于平台期。
- 更有效优化：启动预热消除首轮 5s；ONNX/TensorRT 量化同卡再快 1.5-3 倍；流式识别提前出结果；减少云端 Qwen 调用（简单指令直出已实现）。

## 结论

- 稳态纯语音识别约 0.19-0.25s，满足实时交互要求；首轮 5s 为模型加载，应预热消除；
- 整轮耗时主要被 CARLA 同步 tick（约 0.4s）与 Qwen 云端调用（1.8-4.6s，仅复杂指令）决定；
- 更高算力可让 ASR 快约 1.5-2 倍，但对整轮时长帮助有限；消除冷启动、模型量化与减少云端调用更有效。
