## 在现有环境运行

完整材料根目录下先执行纯文件检查：

```bash
python3 02_源码与部署/scripts/check_deployment.py --profile files
# 官方 B3 环境已具备运行库时再执行 import 检查，不推理模型
python3 02_源码与部署/scripts/check_deployment.py --profile student
```

在**已有 Docker 与本地 OE v3.9.1 base** 的机器上，先运行已有 Student build/export，再构建 CPU controller（不拉取 CARLA 服务端或 CUDA 多 GB 镜像）：

```bash
bash 02_源码与部署/docker/build_and_export.sh
docker build --platform linux/amd64 \
  -f 02_源码与部署/docker/Dockerfile.controller \
  -t challenge-controller-cpu:20261009 .
CARLA_HOST=host.docker.internal CARLA_PORT=2000 \
  docker compose -f 02_源码与部署/docker/compose.controller.yaml up --abort-on-container-exit
```

CARLA 0.9.16 服务端须已在可连接机器运行；这份 compose 只启动客户端和 Student，不启动或下载模拟器。实际场景结果写入材料根 `runs/controller`，RGB 共享目录为 `runs/shared_images`。83 场景工具与 `--scenario-file` 均应以 `02_源码与部署/source` 为 project/cwd；不能把完整材料根误当作该工具的源码根。

## 语音与 GPU 全链路的实际限制

真实音频/麦克风入口额外依赖 torch 与同版本 torchaudio、soundfile、FunASR、ModelScope、PEFT、safetensors、faster-whisper、opencc；源码 `voice_group/requirements.txt` 的 NumPy>=1.26 和 `source/docker/requirements-voice.txt` 的 CUDA torch 2.12.1+cu132 **与 B3 CPU NumPy1.23/torch2.8 基线不同**，不得直接混装到正式 Student 镜像。语音入口 `voice_group/asr_vad.py` 默认设备为 cuda:0，SenseVoice/FSMN-VAD/Whisper 权重和 LoRA 必须预备；实时麦克风还需 PulseAudio `parec`。原语音源文件及依赖说明已随 source 保留。独立语音环境可用 `check_deployment.py --profile voice` 检查 imports/LoRA；检查不会下载或预热模型，也不把转写文本模式当真实 ASR。

当前仍未生成 Docker 镜像实体、SDK 编译 binary、实板计数器或新的 CARLA/语音成绩；本次只补交接工程与文件闭合，不安装 Docker、不改系统、不下载大型权重、不运行模型评测。
