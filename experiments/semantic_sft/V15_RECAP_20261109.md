## 4. 具体改善与退化

### 真正改善了什么

- `TURN_TAIL_V1_012`：原句有“驶过地面橙线后就地停车”。V14 的停车条件退化成“后”；
  V15 恢复为“驶过地面橙线后”。这是实际条件绑定改善。
- `EXP_V2_lane_choice_06_04`：V15 补回右转步骤缺失的“在前方路口”条件。

### 不只是严格文本评分造成的退步

- **矛盾指令处理退化**。Dev 原句“请加速并同时保持车速不变”：
  V14 是 `HOLD + requires_confirmation=true`；V15 变为 `SET_SPEED + false`，且速度为空。
  这不是空格或同义表达差异，而是漏掉冲突、直接给出动作。
- **无条件时反而造条件**。Dev 的“从左侧绕过占道车辆；随后将车速设为23公里每小时；随后靠边停稳”，
  V14 只有三个顺序动作；V15 增造“从左侧绕过占道车辆后”和“将车速设为23公里每小时后”。
  两个条件均不是原句连续片段。顺序词不能自动等于额外的执行条件。
- **多步目标与方向绑定退化**。Dev 的右绕广告牌→回原车道→左绕垃圾车→减速25，
  V14 保留四个动作；V15 合并绕行动作、混淆目标，并把返回车道改成保持车道，变为三步。
  V14 此例仍有条件遗漏，不能说它整体全对；但 V15 的动作顺序确实进一步退步。
- **另一条 Train 能力丢失**。“清洁员通过人行道以后，在前方路口左转。然后减速到18公里每小时。”
  V15 保留清洁员条件，却丢掉原来已抽出的路口位置。动作与速度正确也不代表全字段正确。

“走到底右转”的条件遗漏、关于违章拍照和礼让行人的理解问题，未被本轮加权解决。
`PUBLIC_DRIVING_V1_009` 的“在前方路口”与“前方路口”则涉及严格片段口径，
应与动作错误分开报告；本次没有放宽评分或擅自改标签。

## 5. 问题到底在哪里

### 已有证据支持的判断

1. **硬例不是一种错误。** 条件缺失、条件幻觉、条件边界、目标/方向绑定、动作顺序、冲突确认，
   都会导致 semantic exact 失败，但需要的修复方向不同。只按“是否全对”加权太粗。
2. **整条样本加权不是只修错误字段。** 当前提高的是整段 assistant 答案的 loss；
   原有动作 token 还保留 4 倍字段权重。即使目的是修 condition，也会改变动作及其他字段的更新。
3. **权重均值维持 1 不代表优化轨迹不变。** 15 条样本的总权重占比从 5.12% 变成 7.69%。
   同一批次对照中，含加权样本的 140 次更新，记录梯度范数大于 1 的次数从 45 增到 66；
   不含它们的 630 次从 65 变成 64。它说明相关批次的优化行为确实变化，不能证明具体梯度冲突机制。
4. **动作高分掩盖了其他语义短板。** V14 动作顺序是 73/75，但全字段一致只有 53/75。
   “以前准确率高”需要先对齐指标，而不是把动作准确率当成完整语义正确率。

### 目前不能下的结论

- 不能由这一轮推断“2B 肯定不够”“必须换 7B”或“加权永远无效”。
- 不能说所有失败都是标注错误，也不能为使实验过关而改 Dev 标签或放松 scorer。
- 条件泛化、字段间干扰、样本对比不足是有输出证据的待验证解释，不是已证明的神经网络机制。
- 没有运行独立 Test、CARLA 闭环或生产性能回归；本报告不证明驾驶效果。

## 6. 建议的后续顺序（本次未执行）

1. 保留 V14；停止把 V15 当成下一版候选，不盲目再加权或延长训练。
2. 先在 Train 上建立分类型错误账本：漏条件 / 多造条件 / 片段边界 / 动作顺序 /
   目标方向绑定 / 冲突确认。明确单纯顺序、事件条件、位置约束分别应如何编码。
   任何标签变更须版本化并由负责人审核；不要把仅仅文本边界不同与真实语义错误混为一谈。
3. 在 Train 来源组内检查对照覆盖：有条件与无条件、顺序与触发、明确与矛盾、多步不同目标。
   查清缺口后才补来源独立的训练样本；不要把本次列出的 Dev 错例直接搬入训练。
4. 下一实验只验证一个假设。优先用 Train 的分组留出/交叉验证比较不加权基线和更窄的修复策略，
   同时保护动作顺序与冲突确认，不同时修改权重、标签、提示词和轮数。
   比较全局语义、关键错误类别及逐条回归，不只看 Train loss。
5. 已多次查看的 Dev75 只能用于开发，不能再称独立测试。方案固定后，才使用来源与分组隔离的最终测试，
   不反复利用其错误调参。[数据泄漏与测试隔离原则](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)。

最终目标不是“15 条硬例都背会”，而是在新指令上保持动作、对象、方向、条件和确认边界同时正确。
