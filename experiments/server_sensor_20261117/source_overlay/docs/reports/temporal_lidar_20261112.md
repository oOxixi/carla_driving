# 短窗口多帧 LiDAR 关联实验（2026-11-12）

## 变更

- 新增 `integration/temporal_lidar.py`：最多 4 帧、默认 0.15 秒窗口；以采集位姿把历史点变换到当前坐标。实验开关 `--experimental-temporal-lidar-frames 4`；默认 1（关闭）；需要 `--perception-mode sensors` 和 `--rgb-detector-model`。
- 目标跟踪 ID 和检测框须连续；重叠检测框、缺当前点、时间戳缺失、帧号不连续、轨迹变化或历史点离当前点过远时不使用历史。至少两个历史帧支持、结果距当前点至多 0.35 米，且支持点在水平面上至少相隔 0.1 米。参数为未标定启发式，不能保证目标身份。
- `integration/carla_perception.py` 的试验路径先分配 ID 再关联，输出记录 `RGB_LIDAR_TEMPORAL_UNVALIDATED`；未开启时保留原路径。`canonical_bridge.py` 和接口 schema 增加 `RGB_LIDAR_TEMPORAL`、`UNVALIDATED_TEMPORAL` 标记。独立安全控制和 `PER_OBJECT_UNVALIDATED` 门禁未放开。
- 新增单元测试、感知桥和接口测试，以及静态结果页面 `tools/target_demo/temporal_view/index.html`。未更改默认点云密度，未重启现有 Qwen 服务。

## 验证条件

CARLA 0.9.16、Town10HD_Opt、独立端口 22100、GPU 5；单车静止、目标沿道路约 5 m/s 运动、前车遮挡目标；40、60 米是目标初始路线距离，运动目标在采样时已继续前进。前向 RGB 800×450，32 线 LiDAR，20 Hz。使用 CARLA 真值构造理想 2D 检测框以隔离点云关联；真值不输入关联算法，事后用真值框外扩 0.3 米统计输出位置是否落在目标附近。运动目标的评估位姿与传感器帧按帧号对齐。统计 4 帧预热后的少量帧，单帧与多帧读取同帧传感器数据。

| 场景 | 点/秒 | 单帧有输出 | 多帧有输出 | 多帧输出落在扩展框内 |
|---|---:|---:|---:|---:|
| 40 米静止 | 224000 | 1/8 | 8/8 | 8/8 |
| 40 米运动 | 224000 | 0/16 | 8/16 | 8/8 |
| 40 米遮挡 | 224000 | 0/16 | 0/16 | 不适用 |
| 60 米静止 | 224000 | 0/8 | 0/8 | 不适用 |
| 60 米运动 | 224000 | 0/16 | 3/16 | 3/3 |
| 60 米静止 | 448000 | 0/16 | 11/16 | 11/11 |
| 60 米运动 | 448000 | 0/16 | 3/16 | 3/3 |

较早的 448000 点/秒运动场景曾有 7/16 个多帧输出，其中 1 个落在目标框外，定位为近处静态背景点的重复反射。加入空间多样性检查后的上表复测为 3/16，3 个在扩展框内。这是样本级现象，不证明误关联已经消除。不同密度为不同测试轮次，非严谨总体比较；位置落在框内不是距离误差合格。

完整测试 `python -m pytest -q integration/tests runtime/tests`：1016 passed、2 skipped（包含 CLI 参数约束修改之后的最终回归）；CLI 参数约束也已单独测试。页面通过服务器 127.0.0.1:18766 提供，只能通过 SSH 本机转发访问。
