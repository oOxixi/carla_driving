# Qwen 多模态语音驾驶控制技术方案

## 1. 目标与指标

基础赛道要求覆盖基础操控、复杂避障和应急响应。正式验收门槛为：语音指令解析 P95 ≤ 50 ms、端到端决策 P95 ≤ 150 ms、语音识别准确率 ≥ 95%、多模态语义对齐精度 ≥ 98%、场景任务完成率 ≥ 90%。300 ms 只用于延迟优先的早停，不替代 150 ms 正式门槛。

## 2. 架构与安全边界

链路为 SenseVoice 语音识别/意图槽位 → RGB、LiDAR、车辆状态和环境状态融合 → Qwen 约束决策 → 目标绑定 → 硬安全仲裁 → CARLA 控制。模型只输出严格动作 Schema；非法字段、目标缺失、低置信度、超时和冲突均 fail-closed 为 STOP。制动、低 TTC、红灯等硬规则不交给大模型覆盖。

## 3. 模型路线

默认采用 Qwen3-VL-2B GPTQ INT4（revision `f91db2369bd00e7ec20bf09b6a0080cdb26aefa5`），固定 64 个视觉 token、256 图像边长和压缩提示词，通过 vLLM 的 Marlin INT4 线性核运行。FP8 2B 仅作为同规模复核路线。8 GB RTX 5070 负责验证链路和部署契约，A800 负责生成最终正式指标。

## 4. CUDA 13.2 可迁移部署

Qwen 与控制器均使用 Linux CPython 3.12 离线 wheelhouse。vLLM 从固定源码构建 CUDA 13.2 wheel，并保留 sm_80、sm_120 与 PTX 兼容目标；CARLA 0.9.16 Python 客户端和 ScenarioRunner revision 固定。模型权重、数据集、wheel、镜像和运行日志均以 SHA-256/immutable revision 关联。

## 5. 数据与评测定义

冻结数据覆盖普通话、方言/噪声语音、动态 RGB、LiDAR、车辆状态及代表性场景。正式 `evaluate` 顺序固定为预检、5 次预热、10 个动态样本延迟、正确率、三类 CARLA 场景。若端到端 P95 > 300 ms，立即停止正确率和场景；只有接近 150 ms 后才运行 30 分钟稳定性。

| 指标 | 晋级线 | 当前 RTX 5070 证据 |
|---|---:|---|
| 场景任务完成率 | ≥90% | NOT_RUN |
| 语音指令识别准确率 | ≥95% | NOT_RUN |
| 多模态语义对齐精度 | ≥98% | NOT_RUN（仅有 10/10 本地代理契约诊断） |
| 端到端决策响应延时 | ≤150 ms | NOT_RUN（仅有 Qwen 热请求诊断） |
| 指令解析延时 | ≤50 ms | NOT_RUN |

## 6. 已有 RTX 5070 原始证据

`metrics/reference_5070` 直接保存两份原始 JSON：INT4 固定图热请求 5 次预热后 10 次测量，P50 74.03 ms、P95 83.85 ms、max 84.19 ms；另一个本地代理集合动作/目标契约 10/10。二者不等于正式全链或物理闭环结果，清单中的 SHA256 用于防止结果被重算或静默替换。

## 7. A800 复现

先以 `a800-safe` 预检和评估，再停止服务并切到 `a800-optimized`。每个指标只从 A800 新生成的 run manifest 和原始日志读取；不得复制 RTX 5070 数值。A800 当前状态：`NOT_RUN`。

## 8. 交付与限制

源代码提供 Docker-only 一键脚本、只读复现 Notebook、固定 revision 下载脚本、指标/原始日志与提交物校验器。当前提交不包含模型权重、`image.tar`、技术方案 PDF 或闭环视频；校验器会明确失败，直到操作员提供真实产物。不存在的正式结果统一记为 `NOT_RUN`。
