同帧对照：单帧与多帧

条形长度表示“给出位置的帧数 / 评估帧数”。右侧列出位置落在目标扩展框内的数量；样本很小，不应视为总体准确率。

单帧多帧默认 224,000 点/秒；加密组 448,000 点/秒

仅统计预热后的帧；单帧和多帧使用同一批相机与 LiDAR 帧。两种密度属于不同测试轮次，不能当作总体结论。

多帧如何工作

  • 1只保留短窗口内、编号和图像框连续的目标点。
  • 2利用传感器位姿补偿自车运动，并要求当前帧也有点。
  • 3历史帧、空间位置和点的多样性需共同满足条件；检测框重叠时不使用多帧累积。
  • 4证据不足时输出“未知”；输出位置也标为“未验证”。

一次关键误关联

较早的 60 米运动试验中，近处一个静态背景点连续出现，被错误关联到远处车辆。

发现：旧实验规则有 1 / 7 个位置落在目标扩展框之外。
调整：增加不同空间点的支持要求，避免把同一个反射点重复计数。
复测：该组为 3 / 16 帧有输出，3 个位置均在目标扩展框内；不能据此推断其他场景不会误关联。

如何理解这些结果

CARLA 0.9.16 · Town10HD_Opt · 前向相机和 32 线 LiDAR · 运动目标约 5 米/秒。40、60 米是目标初始路线距离，运动目标在采样时已继续前进。相机检测框由仿真真值生成，仅用于隔离评估点云关联；这不是实际检测器识别率，也不是整车闭环驾驶成绩。目标扩展框仅用于事后评估，真值未输入关联算法。

上述理想框实验未覆盖真实目标检测；真实流程只测了顶部列出的四次运行，仍未覆盖更多遮挡、天气、传感器故障、定位误差和完整时延。每次观测样本很少；位置在框内不等于距离精度合格。默认点云密度的 60 米静止目标在本轮为 0/8，说明距离问题尚未解决。
